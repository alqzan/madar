# M0-T05 — Presentation privacy supplement

2026-10-11, codex, Top design note. Scoped source inspection at `cf60172`; no build, authentication, simulator or snapshot test was run. This supplements M0's architecture without changing defaults, schema or the one-minute background authorization lease.

## Confirmed gaps

Authority: `14-shared.md` §8.10, especially lines 155–157, 183–189: cover protected presentations at `.inactive` before the app-switcher capture; protected text must not remain in VoiceOver; explicit export passes the lock first. User screenshots are not prevented.

- `MadarLock.swift:150–153` places the inactive cover on root SwiftUI content. `MadarApp.swift:42–44` applies that gate below presented UIKit/SwiftUI sheets. A native share or another modal can sit above this cover. This is a structural coverage gap; an actual leaked switcher frame has not yet been demonstrated.
- `.export` already maps to the existing notes/app protection in `MadarLockController.requiredFeature`, but neither export service nor the direct ShareLinks in `BackupSettingsView.swift:180–192` requests it. Default `notesOnly` permits opening the settings shell, so full-data plain export currently bypasses the notes lock. A previously generated share URL also lacks a fresh presentation check.

## Minimal architecture

Keep storage, backup lease/quiescence, RA2 blind prayer writes, snapshots and existing `AppPrivacyService` redaction intact. Add presentation plumbing at the app boundary; no room or new setting is needed.

1. **Scene cover:** a small `@MainActor ScenePrivacyPresenter` owns one opaque cover window attached to the exact hosting `UIWindowScene`. Install a scene bridge inside each WindowGroup instance; discover its scene from the hosting view's window, never `connectedScenes.first` or an app-wide key-window guess. Keep a weak scene reference and unregister/release on disconnect. Put the cover above app-owned sheets/presentations; preserve the normal key window and do not intercept OS authentication. Root protected gates remain the data-access/VoiceOver guard. The cover exposes only a generic protected label, uses modal accessibility semantics, and hides app-owned presented content from accessibility while covered.

2. **Synchronous cover, asynchronous redaction:** on the owning scene's native will-deactivate callback, show the cover synchronously with no animation, before starting any Task or awaiting redaction. Repeat fail-closed coverage for background, protected-data unavailability, lock/scope-change and unknown lifecycle states. Forward one ordered transition to the existing controller, avoiding duplicate app-level and scene-level events. SwiftUI `.onChange` remains a secondary signal, not the snapshot boundary. A second scene becoming active must never uncover the first scene. Do not promise protection for a screenshot the user takes while actively viewing authorized content.

3. **Authorization versus presentation:** maintain the current scope and 60-second background lease; `.inactive` covers immediately without expiring the lease. Returning before expiry may reuse the lease only after redaction recovery and authorized data rebinding complete. At/after 60 seconds, require authentication again. Cover removal requires that scene to be active, its lock requirement satisfied, and redaction successful. Authorization belongs to the controller; scene visibility and native presentation ownership belong to the scene presenter. A lease in another scene cannot remove this scene's cover. A scope change invalidates all affected scene presentations.

4. **Async correctness:** stamp authentication and pending presentation requests with request ID, privacy generation and scene lifecycle epoch. After every await, verify the request is still current and the scene/lock conditions still permit commit. If an OS auth prompt causes temporary inactivity, retain its request but keep the cover; expose content only after a valid active transition. Background, scope change, disconnect or cancellation invalidates the request. Late completion must not unlock, uncover, present a sheet, clear a newer request's state or refill protected view models. Stale authorized data must be redacted again. Use a test-only authentication/service seam; never a production environment variable that bypasses authentication.

5. **Explicit export gate:** request `.export` before plain-file creation or explicit encrypted export/key setup, and revalidate before publishing the result URL and before presenting a cached file. Respect the existing `.app`/`.notesOnly`/`.none` mapping; cancellation/refusal creates no export, configures no key and presents no file. Full-data export must also respect the existing always-protected `.privateNote` rule if its payload includes private notebook records; this is enforcement of §8.10, not a new default. A presence/metadata query may select that requirement without fetching private text before authorization. Automatic encrypted backups retain their existing unattended behavior.

6. **Native share state:** direct ShareLink cannot await authorization immediately before native presentation. Either expose it only through a current protected gate with reliable revocation, or use a narrow native activity-controller adapter invoked by an explicit authorized button. Track its request/scene and cached URL as protected presentation state. On inactivity cover it synchronously; revoke pending presentation and clear its sensitive UI state on lock/lease expiry/scope change. Do not automatically reopen sharing after authentication or return from background: require the user's explicit tap. An external share action already completed cannot be recalled. Retain completed export files according to the existing policy; revoke UI references rather than deleting unrelated artifacts.
