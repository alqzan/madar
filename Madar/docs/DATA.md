# MadarData — M0 data foundation

Built against the approved working dictionary v3 (2026-10-10). Store schema is independently versioned v1. Reference material is the rechecked handoff; its four conflicting contracts are superseded by `START-M0.md`. No old or user store was opened or modified.

## Implemented

- 61 public SwiftData models generated from the working dictionary: 55 synced, six device-only. Defaulted/optional fields, primitive arrays, UUID foreign keys, no uniqueness constraints or SwiftData ownership relationships. `Media.data` uses external storage. Run `python3 Packages/MadarData/Scripts/generate_models.py` from any directory to regenerate models/schema/resource copies. The script never edits the specification.
- One factory: `MadarContainerFactory.makeInMemory()`, `makeLocal(at:)`, `makeAppGroup(identifier:cloudKitContainerIdentifier:)`. Synced and device configurations are disjoint; local harness explicitly disables CloudKit. App Group mode reads the device iCloud preference before creating the complete container. A schema-version sidecar fails closed for malformed/newer versions before opening stores. An explicit v1 migration schema/plan is present; no prior production schema is supported yet.
- `RowMerger(context:).run()` operates on context-confined physical model instances and saves once. It handles natural-key union, deterministic winner ordering, persisted alias foreign-key remapping, sticky tombstones, explicit restoration, same UUID physical duplicates, Entry-owned MarginNote cascade, exclusively owned entry media, session/book cascades, Account balance pairing, HabitLog maximum completion, and HadithProgress union/earliest exceptions. Transactions remain id-only. Trip/plan/recovery invariant repairs and envelope allocation totals are included. `resolve` chooses a non-alias physical winner when two records share a logical UUID; an ignored duplicate can therefore alias that same logical UUID without turning the winner into an alias.
- Tombstone contract: `deletionBarrierAt` retains the maximum deletion timestamp. `restoredAt` is written only by explicit restoration; it must be greater than the barrier. Ordinary edits never revive a deletion, including a singleton carrying a barrier but no `deletedAt`. Restore sets `deletedAt` to nil while keeping the barrier. Fresh deletes must set both `deletedAt` and `deletionBarrierAt` to their monotonic write timestamp.
- Day One identity: `Entry.sourceBranch` is empty for the primary source identity. The stable keep-both branch is `StableIdentity.dayOneBranch(canonicalSource:)`, SHA-256 of the canonically serialized incoming source entry. Reconciliation uses `(source, sourceID, sourceBranch)` and retains original source provenance, dates and media references. The actual Day One importer and canonicalization of its input remain M3 work.
- Settings facade loads all 127 schema definitions. Defaults are read without creating synced rows. Sync/device/layout values persist in their designated stores; layouts use only LayoutState. Type/options/ranges and composite structural contracts are validated. Invalid persisted values fall back to the default and log the key once, without logging the value. Set/reset/resetMany/preset transactions have durable receipt-backed undo, reject undo after a later edit, and consume undo once. Preset window is `appliedAt <= now < appliedAt + 60 seconds`; undo executes immediately. Receipt expiry is independently seven days.
- Atomic integration API: `SettingsStore.stage(_:presetOnly:now:)` validates a batch, returns prior values, stages changed values, and performs no save. A CommandBus adapter owns its receipt/save/rollback. `prepare(_:for:now:)` is a staged single-value write. Convenience set/reset/preset APIs save with their own receipt. `writerIDForWrite` stages the install identity, reused across reopen; every settings mutation uses it. Reads and invalid prevalidation create no identity row.
- Backup codec uses PBKDF2-HMAC-SHA256 at 600,000 iterations (CommonCrypto), AES-256-GCM (CryptoKit), random salt/prefix and indexed 1 MiB chunks with final flag/header AAD. The plaintext is an Apple Archive of every synced model's JSONL, manifest counts/byte sizes/SHA-256, and media files. Device-only records are excluded. Input is bounded, paths are checked, and all manifest files/row counts/checksums/typed fields are validated in a fresh in-memory container before a destination is touched. `BackupRestore.merge` retains backup timestamps, merges deletion barriers and is idempotent. No populated-store replace API is exposed.

## Verified

`cd Madar/Packages/MadarData && swift test` passed **23 Swift Testing tests** on the owner's Apple silicon Mac, macOS 27.0.1 build 26A434, Swift 6.4, deployment baseline macOS/iOS 26. The final full report is `Artifacts/data-tests-final.log`. XCTest's zero-test preamble is separate from the successful Swift Testing run.

Tests create real SwiftData in-memory containers and temporary disk stores. They verify all model configurations, disk persistence/newer-store refusal, deletion versus later stale writes, explicit restoration, singleton barriers, deterministic winner/FK alias handling, owner cascade versus shared media, completion merge, ImportLink target merge and child remapping, same UUID offline seed/deletion duplicates, stable two-branch import identity, distinct computed date/word keys, defaults/invalid settings/device isolation, atomic preset rejection/dependent batch undo, immediate undo/strict 60-second deadline/seven-day retention, and monotonic writes.

The backup fixture includes every synced model, a tombstone, an alias, a photo and audio. Export/decode preserves every record/media byte; fresh-store merge works and the second merge writes nothing. Wrong password, truncation, flipped ciphertext, newer schema header and multi-chunk reordering are rejected. Wrong password/truncation/newer header leave an existing temporary disk store **byte-identical**. Missing live media is rejected during export. This is not an authenticated malformed-archive missing-media restore fixture.

## M0 gates still open

These are required follow-up integration/device gates, not claimed complete:

- Provisioned App Group/CloudKit entitlement preflight, real private database synchronization, remote-history consumption, account switching and the two-device same-row conflict characterization. The optional CloudKit configuration exists but has not been exercised. The sidecar is a local version gate, not proof of a signed app's entitlement or CloudKit schema readiness.
- App/Intent concurrent-process natural-key writes are the CommandBus adapter's integration responsibility. No cross-process lock is implemented inside MadarData.
- Populated-store restore-replace, automatic backup before destructive operations, user preview/confirmation, schema migration mapping, snapshot regeneration/history-token reset, cancellation/retention/background scheduling and Keychain handling. Backup validation currently uses a main-actor temporary ModelContext and bounded in-memory archive data; production UI must provide an asynchronous progress/cancellation coordinator before exposing large restores.
- Quran frontier, PageSchedule and current CyclePolicy cache rebuilds require their room engines. Recovery repair currently chooses among uncancelled plans; it does not calculate completed recovery from the future Quran scheduler. Soft-restrict account/card/category/envelope UI archival requires the room commands. Restoring a parent does not automatically restore child tombstones yet.
- Full semantic validation of every room-specific row, exact reader font registries and historical trackingStart editing policy. M0 UI should expose only connected core customization controls. Arabic word normalization is the specified baseline; full search normalization belongs to the room search module. Statement/Cycle civil-date grouping currently uses UTC date buckets and needs event/place policy integration before money data import.
- Actual Day One ingestion/canonicalization and old My-dream migration field maps remain their room milestones; the M0 identity helper alone is not an importer. Default money category seeding is likewise M5 work.

Do not use this package alone as evidence that M0's complete device, restoration or synchronization gate has passed.
