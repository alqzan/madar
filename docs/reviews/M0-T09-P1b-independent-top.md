## Findings

1. **High — P1b-I01: explicit restoration bypasses first-key and safety-export authorization.** `Madar/App/AppBackupService.swift:163–169`; `Madar/Packages/MadarData/Sources/MadarData/BackupCoordinator.swift:94–108,116–121` (lines at `48a3fe4`). Restore reads/configures the backup credential before any scene authorization, then captures all current rows in an automatic safety export and promotes restoration. Under the default `notesOnly` scope, Settings is reachable without notes authorization; under `none`, current private NotebookNote rows still require device authentication. The first safety key may be derived from the imported file's known password while the existing protected store is captured. The candidate also omits the restore request/ticket revocation and the validations after suspension/before promotion present in `33ab2ec`, so a scene lock/background/scope change during derivation does not revoke this operation. **Fix:** integrate the reviewed restore repair: owning-scene `.export` plus `.privateNote` when current stored private rows, including tombstones, enter the safety payload; authorization/key setup inside the restore writer barrier; owned request/ticket cancellation; validation after asynchronous work and before promotion. Preserve the allowed, refused and delayed-derivation revocation regressions (`test_M0P1b_01_*`) and the package refusal-before-key/safety/promotion test removed by this delta.

2. **High — P1b-I02: opening backup Settings loads the secret merely to show configured status.** `Madar/Packages/MadarData/Sources/MadarData/BackupCoordinator.swift:15`; `Madar/Packages/MadarData/Sources/MadarData/BackupKeyStore.swift:32–37`; called from `Madar/App/AppBackupService.swift:48–54` (lines at `48a3fe4`). `hasConfiguredKey()` calls `load()`, whose Keychain query explicitly returns credential bytes and decodes the key. Settings status/preview reach that path before explicit export authentication. The candidate drops the reviewed metadata-only `exists()` interface and Keychain query, so the zero-key-read refused-export tests do not establish the broader boundary advertised by the design. **Fix:** retain the `33ab2ec` presence query (`kSecReturnData = false`) and use it for configured status. Keep actual unattended automatic backup credential access intact. Restore both configured/unconfigured status tests and the allowed automatic-backup test (`test_M0P1b_02_*`) so a no-secret status result cannot pass by disabling backups.

3. **High — P1b-I03: an already presented private file survives owning-scene authorization revocation.** `Madar/App/ScenePrivacyPresenter.swift:29,93–99,114–117` (lines at `48a3fe4`). The presenter observes generic state only, retains no activity authorization, and retires activity only on a native lifecycle transition or another controller's scope notification. Owning-controller `lock()` or a local scope change invalidates the export/private-note ticket while the native activity retains its file. After generic app recovery/authorization, `synchronize()` checks only `.app` and may uncover that stale share, particularly under `none`/`notesOnly`. Even lifecycle dismissal drops activity state immediately without holding the cover until native removal completes. The repaired tip's revocation observer, stored ticket, stale-ticket check and dismissal-completion cover are all absent. **Fix:** integrate those reviewed presenter guards from `33ab2ec`; retire the request synchronously on the owning controller's revocation, hold coverage through native dismissal completion, and require a fresh explicit share tap with payload authorization. Keep the allowed fresh-share assertions alongside `test_M0P1b_03_activeLockRetiresPrivateShareIncludingScopeNone` and `test_M0P1b_03_localScopeChangeRetiresPrivateShareBeforeGenericAuthorization`.
